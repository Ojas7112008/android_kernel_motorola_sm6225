## Problem and resulting behavior

The vendor FUSE inode cache uses nodeid or a backing-inode pointer, while directory records report attr.ino. A normal ilookup(sb, emitted_ino) can miss a still-live marked inode. The previous consumer intentionally exposed the entry when its named dentry was absent rather than guessing an unrelated physical /data inode. That specific live-inode/cache-miss case now filters through [fs/susfs_fuse.c](../fs/susfs_fuse.c), selected alongside the path core in [fs/Makefile](../fs/Makefile).

[fs/readdir.c](../fs/readdir.c) retains the named-child check. Its FUSE fallback consults an index keyed by the actual FUSE superblock and full 64-bit reported inode number. Physical inode numbers from other superblocks and FUSE node IDs are not substituted. Native and compat emitters retain the same output/cookie/error behavior; the new lookup performs no VFS lookup, daemon request, allocation, wait or inode/mount reference acquisition.

The index tracks all live published FUSE objects, including unmarked ones. If every matching live candidate is marked and is owned by another UID, the entry is hidden for an umounted app task. A known unmarked or current-owner peer with the same reported number makes the number-based fallback visible; the named-child check can still identify a specific cached object. This avoids treating a known different object as hidden merely because its reported number collides. It intentionally prefers visibility for an ambiguous identity.

## Lifetime and locking

[include/linux/susfs_fuse.h](../include/linux/susfs_fuse.h) defines an internal typed contract and a 40-byte entry on the tested 64-bit host. It is appended, behind CONFIG_KSU_SUSFS_SUS_PATH, to the vendor-private [struct fuse_inode](../fs/fuse/fuse_i.h). Existing private fields keep their offsets; the object size increases when PATH is enabled. Native inode, vfsmount, address_space and SUSFS 2.3.0 payload layouts/versions/constants are unchanged. All FUSE objects and consumers must be rebuilt together; prebuilt-module compatibility is not certified by the host fixture.

The native [FUSE lifecycle](../fs/fuse/inode.c) initializes the entry immediately after allocating the private object. An uninitialized native inode is not dereferenced by this initialization. Allocation failure exits never publish it. After native attribute/owner updates, while fi->lock remains held, the entry is moved to its reported-number bucket and receives the current mapped kuid owner. The original full attr.ino is used; no narrowed node-ID or userspace-UID interpretation is added. This also follows the native backing-attribute conversion used with BPF.

Readers and publishers use one IRQ-safe index spinlock. A reader checks the public mapping marker under that lock and retains no entry/inode pointer after unlock. fi->lock precedes the index lock on update; readers/teardown never acquire fi->lock from the index. No VFS, allocator, reference drop, workqueue scheduling or grace-period wait occurs inside the index lock. The host lock is a pthread model; native IRQ/lockdep behavior is still unvalidated.

Eviction removes the entry before mapping/page-cache teardown and clear_inode. The direct free callback removes it again, idempotently, covering inode-initialization failure/direct destruction paths. Native DAX cleanup, forget requests, BPF/backing-reference drops and RCU-delayed free remain in their existing code. Since the entry is embedded and readers serialize with removal, it needs no allocation, extra RCU callback or retained inode/mount/superblock reference. Reusing inode memory or reported numbers cannot reuse an old entry after proper teardown. The static table has 256 bucket heads; occupancy follows the live FUSE inode population, with one entry per object and no persistent command-created registry.

The index is built into the checked SUS_PATH target. Its init/update/forget providers are exported GPL symbols for a modular FUSE caller; the built-in directory consumer calls the built-in query. Tests reject building the index without PATH/SUSFS/the selected provider or as a module. Real Kbuild/modpost/CFI and module unload are still pending. Removing the inserted PATH guards reproduces both native FUSE source files exactly.

## Limits and next boundary

This closes the reproduced dentry-cache gap for a live published marked FUSE object with a coherent reported number. It does not make arbitrary daemon metadata unique or immutable. A different reported number arriving before its attribute publication, a not-yet-materialized duplicate object, BPF-rewritten records, a removed inode or a concurrently replaced name cannot always be identified from the plain record alone. Known duplicate objects are deliberately visible when ownership/markers disagree. Readdirplus emits before its native link/attribute refresh; that order is preserved. These metadata/identity races and the conservative ambiguity policy must be included in the production-enable review, rather than described as complete invisibility guarantees. Eviction loses the transient mapping marker itself; deferred path registration can re-mark a new inode on a later pass.

The global spinlock and table add work to FUSE attribute publication and directory filtering; real contention/large directory performance needs kernel measurement. The native object/RCU/IRQ/daemon/BPF/DAX/namespace/stacked behavior and full ARM64 compilation remain unvalidated by host mocks. No path hiding operation is an FD-revocation or access-control guarantee.

Next review the separate open/create fallback, overlay/backing identities, concurrent name/mount traversal and the metadata limits above, then decide PATH enablement and truthful feature output together. Other feature bodies/payloads, mount IDs/namespaces, the pinned build workflow/toolchain, actual ARM64 builds and separately approved boot/runtime testing remain in order. No compatibility check/version bypass, commit, push, CI dispatch, image/release, flash or device operation is performed here.
