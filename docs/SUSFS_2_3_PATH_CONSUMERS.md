## Implemented consumers

[fs/namei.c](../fs/namei.c) now checks the actual inode after native lookup/revalidation in lookup_dcache, __lookup_hash, lookup_fast and __lookup_slow. Referenced hidden results return ENOENT and drop exactly the caller's reference. The underlying positive dentry is neither invalidated nor changed into a negative result. Native invalidation for a failed revalidation remains intact. Cold lookup ownership completes with the native d_lookup_done before dropping an allocated or replaced result. Alias/error returns retain native ownership.

An RCU fast hit is inspected only after child/parent sequence validation and successful native revalidation. A hidden hit returns ECHILD without dput, allocation, waiting or d_lookup_done. The native filename caller retries in reference mode; that retry returns ENOENT. Existing miss/unlazy/revalidation fallbacks are retained. step_into checks the resolved inode after native mount traversal, so a marked mounted root is also filtered. Its reference-mode rejection transfers the path into nameidata for native cleanup, preserving conditional mount-reference ownership. RCU rejection performs no reference transfer.

link_path_walk checks the current directory after native may_lookup, preserving Motorola inode_permission2 and mount arguments/errors. complete_walk also covers a marked starting directory resolved as a root or dot, after successful native weak revalidation where required. Filesystem revalidation errors retain priority. No added nameidata state/lookup flags are necessary. Native filename allocation, putname, credential/audit, permissions, may_open, atomic_open and vfsmount layouts remain unchanged.

lookup_open checks referenced cached and newly looked-up inodes before creation/open/truncation effects. Filtered umounted app tasks use the existing no_open lookup/create fallback instead of allowing atomic_open to open a cold existing inode before it can be checked. Nonfiltered tasks retain the atomic route; owner exceptions remain in the real inode predicate. A source inventory finds lookup and create providers in all nine native inode-operation tables with atomic_open. This does not validate their runtime/remote race behavior or performance. Ext4, F2FS, FUSE and overlay are enabled in the legacy bengal-perf_defconfig; the eventual final config still needs validation.

[fs/readdir.c](../fs/readdir.c) filters all five emitter variants: native old_readdir/getdents/getdents64 and compat old_readdir/getdents (compat getdents64 shares the native 64-bit helper). The borrowed directory dentry comes from the held file path and remains valid through iterate_dir. No added inode/path reference outlives that call. The helper uses the native d_hash_and_lookup, including filesystem-specific name hashing, and puts every acquired dentry. Its non-FUSE inode-cache fallback pairs ilookup/iput within the opened directory's own superblock. It performs no recursive filesystem lookup or /data path resolution under the directory inode lock.

The task/owner/marker predicate is unchanged. Dot/dotdot are preserved. Hidden entries return zero before record size, inode-width and user-copy checks, so they consume no buffer bytes, do not update previous records, and allow the filesystem to advance its own cookies. For the native emitters that validate names, malformed names still fail before filtering; the native compat getdents emitter's existing name-validation behavior is preserved. Visible entries, partial copies, signals, last-record offsets, held FD position, LSM checks and native errors retain their original code.

The native [dcache implementation](../fs/dcache.c) is unchanged. Task filtering belongs to these namei consumers, rather than global cache lookup/allocation/publication: other tasks must retain the same real dentry, and a borrower must not complete another lookup's wait queue. Removing only the newly inserted feature guards reproduces both native source files byte-for-byte.

## Deliberately unresolved coverage

The production aggregate still rejects SUS_PATH; enabled-feature output does not advertise it. Initial consumer implementation and passing host tests do not close that gate.

FUSE's vendor implementation hashes cached inodes by nodeid or backing-inode pointer, while emitted ino/i_ino can differ. The pinned 5.10 patch selects the /data superblock for every FUSE enumeration. This is not a verified identity translation for an arbitrary FUSE mount or this vendor's BPF/backing route. This port does not make that substitution. A cached FUSE child can be filtered by its actual inode; if that child has left dcache while the inode is still marked/live, enumeration can reveal its name. The host suite explicitly demonstrates this gap and does not count it as complete FUSE coverage. Resolve this with a cache-independent, lifetime-safe identity contract before enablement; audit ordinary/plus/cached/BPF readdir, aliases and backing-inode ownership. A missing native inode also loses a transient mapping marker; the existing deferred registry can re-mark replacement inodes but is not continuous visibility enforcement.

The separate lookup/create fallback needs filesystem integration and concurrent mutation review. Network filesystem semantics, external daemon changes, overlay/backing identities, native dcache/RCU concurrency and already-held FD effects are not established by the models. Path hiding is not FD revocation or an access-control guarantee. The existing fake-qstr provider is retained from the previous checkpoint for header identity/provenance but has no hiding consumer.

## Executed validation

[test_path_consumers.py](../scripts/susfs/test_path_consumers.py) compiles actual namei functions, the whole Motorola readdir object, the actual inode predicate and the vendor d_hash_and_lookup function. VFS/cache/sequence/revalidation/lock/credential/mount/FD/copy behavior around them is modeled explicitly in [the fixture](../scripts/susfs/test_path_consumers.c). The models do not execute a real syscall, filesystem, daemon or native concurrent cache.

Four configurations pass with Clang 21.1.8, ASan/UBSan configured to halt on undefined behavior: PATH off/on crossed with compat off/on. Tests cover cache/cold/alias/error results, references and lookup completion, RCU sequence and retry behavior, native permission ordering, root/system/unclassified/multi-user/owner gates, mount-path transfer, marked starting directories, symlink follow selection, hidden O_CREAT/O_EXCL/O_TRUNC and normal creation/read-only/errors, all five record paths, hidden-only EOF, insufficient/partial buffers, inode overflow, user-copy/final-cookie faults, signals, malformed names, FD/LSM failures, dot entries and FUSE cache limits. Mutation controls fail when atomic open precedes filtering or skipped entries return a buffer error. No production guard is relaxed by those controls.

Affected access/stat, path-core, core-foundation and automatic SELinux regressions are recorded alongside the consumer results. Other unchanged test inputs are verified against their existing passing reports. All revision/version/provider checks remain in place. Source-only kernel-stage checkpatch reports zero errors/warnings; existing imported-header/provider findings remain documented separately. See [PORT_LOG.md](PORT_LOG.md) and .backport-context/audit/path-consumers for final integrity evidence.
